# バクラク カード利用報告の画面操作

ブラウザ操作でカード利用報告の下書きを作るまでの手順。**探索せずに済むよう、押す対象を先に示す。**

セレクタは実運用で確認したもの。バクラク側の画面変更で合わなくなることがあるため、見つからない場合は [セレクタが合わない時](#セレクタが合わない時) を参照。

## 全体の流れ

```
未申請カード明細一覧
  ├ 該当行が無ければ → 申請済タブを確認（既に申請済みなら終了）
  └ 条件に合う行をクリック
      └ 「申請する」→「カード利用報告」
          └ ファイル添付 → 購買申請の紐付け → 内訳 → 内容・メモ(空欄可)
              └ 「下書きに保存」
```

一覧URL: `https://workflow.layerx.jp/my_owners_unified_card_transactions`

タブはクエリ文字列で切り替わる。

| タブ | URL |
|---|---|
| 未申請 | `my_owners_unified_card_transactions`（既定） |
| 申請済 | `my_owners_unified_card_transactions?cp=1&t=APPLIED` |

## 1. 未申請明細から対象を選ぶ

未申請明細の行: `tr.cursor-pointer[role=row]`

各行から読める値:

| 項目 | セレクタ（行内） |
|---|---|
| 利用日 | `.authorized-at`（`YYYY-MM-DD` 形式） |
| 金額 | `.amount`（カンマ区切り） |
| カード利用名 | 行のテキスト全体に含まれる |

**照合の条件**（すべて満たす行を選ぶ）

- カード利用名: 行テキストに、確定したカード利用名が **部分一致**で含まれる
- 利用日: 完全一致、または対象年月（`YYYY-MM-`）で前方一致
- 金額: 完全一致、または部分一致

### 該当行が無い時は、まず申請済タブを見る

**未申請タブに該当行が無くても、すぐ「明細が無い」と判断しない。既に申請済みのことがある。**

申請済タブ（`?cp=1&t=APPLIED`）を開き、同じ条件で照合する。一致する行があれば、その行の申請名リンクが既存の申請である。**新規に下書きを作らず**、申請URLとステータス（下書き / 進行中 / 承認済）を利用者に報告して終了する。

この確認は既に開いている一覧上の `evaluate` だけで済み、1分もかからない。**二重申請は誤った経費を承認フローに乗せる**ので、必ず実施する。

申請済タブにも無い場合、原因は2つに分かれる。

- 未申請タブが0件 → カード明細がバクラクに未取り込み。取り込まれるまで申請できないと伝える
- 行はあるが条件に合わない → 読み取った金額・カード利用名・年月のどれかが実際とずれている。**勝手に近い行を選ばず**、読み取った値と一覧の内容を提示して利用者に確認する

## 2. 申請フォームを開く

対象行をクリックした後、

1. ボタン「申請する」をクリック
2. メニュー項目「カード利用報告」をクリック

## 3. フォームを埋める

### 順序: ファイル添付を最初に

**ファイル添付 → 購買申請の紐付け → 内訳 → 内容・メモ の順で埋める。**

理由は3つ。

1. 添付をきっかけに、バクラクが明細項目を**自動入力する**ことがある。先に手入力すると、その値と競合するか入力が無駄になる
2. **ファイル添付と購買申請の紐付けは同じセル内にある。** セルを一度開けば両方処理できる。逆順だと同じセルを2回開くことになる
3. 添付は工程中で最も手数が多く失敗しやすい。先に片付けるほど手戻りが小さい

**入力前に、既に値が入っていないか必ず確認する。** バクラクは過去申請や添付ファイルから自動入力することがあり、上書きすると誤った値になる。

### ファイル添付

**「ファイルは必須です」の表示が無ければ、既に添付済みなので何もしない。**

表示がある場合。**ダイアログが2段になっており、同名のボタンを2回押す**点に注意する。

1. `.request-col-content` をクリック（セル内にボタンが直接現れる。中間のリンクは無い）
2. ボタン「明細にファイルを追加」をクリック → 1段目「ファイルの追加／編集」が開く
3. 1段目の中の**ボタン「明細にファイルを追加」をもう一度クリック** → 2段目「アップロード」が開く
4. 2段目はタブ「新規アップロード」が選択済み。ボタン「ファイルを選択」をクリックしてファイルチューザーを開き、`browser_file_upload` にパスを渡す
5. ボタン「アップロード」をクリック（ファイル選択前は disabled）
6. アップロードが終わると2段目は自動で閉じ、**1段目が残る**。`button.close` で明示的に閉じる
7. 「ファイルは必須です」が消えたことを確認する

閉じたあと、**自動入力が走っていないか各項目を確認してから**次に進む。

### 稟議の紐付け

紐付ける稟議名が確定している場合のみ実施する。

**判定表の稟議は、原則として明細行の「購買申請」に紐付ける。トップレベルの「関連申請」欄は使わない。**

両方に同じ検索ダイアログが出るため取り違えやすい。過去の承認済み申請を見ると関連申請欄は空で、稟議は明細行の購買申請に入っている。関連申請に入れると後で付け替えが必要になる。

**購買申請（通常はこちら）**

ファイル添付で開いたセル `.request-col-content` の中に、紐付けボタンが並んでいる。

- 紐付け済み判定: `.purchase-request-title span[id*='selected-purchase-request']` が存在すればスキップ
- 開く: ボタン「購買申請を紐付け」をクリック
- タブ「閲覧できる申請」をクリック（**このタブ切り替えを忘れると検索結果が出ない**）
- 検索欄に条件を入力
  - 番号: `#input-group-num [id*='__BVID__'].form-control`
  - 件名: `#input-group-title [id*='__BVID__'].form-control`
  - キーワード: `#input-group-full-text [id*='__BVID__'].form-control`
- 結果の行: `.tab-pane.active tr` 内の `button`（ラベルは「選択」）
- **結果が0件なら「閉じる」で閉じ、稟議は未紐付けのまま進める**（下書き保存自体は継続する）

**複数ヒットした時の選び方**

同じ稟議名が年度ごとに作られているため、複数ヒットするのが普通である。**先頭を選んではいけない。**

- 申請名に含まれる期間表記（例: `（26年1月〜12月）`）と、**請求書のサービス期間**を照合する
- 検索結果の行には消化率・購買金額・利用可能額が表示される。**請求額が利用可能額に収まる**ことを確認する
- 期間が判断できない、または枠を超える場合は選ばず、候補を提示して利用者に確認する

**関連申請（判定表が明示している場合のみ）**

- 紐付け済み判定: `[id*='group-related-request'] .request-view` の中身を見る（空なら未紐付け）
  - `.card-body` では判定できない。この要素は存在しない
- 開く: `[id*='group-related-request'] button.btn-primary`（ラベルは「申請を選択」）
- 以降は購買申請と同じ手順

**紐付けを解除する**

誤って紐付けた場合:

1. 対象グループ内の `svg.icon-close` をクリック
2. 稟議名に取り消し線が付き `.deleted` クラスが付与される（この時点では未確定）
3. 「下書きに保存」で確定する

### 内訳

セレクタ: `[id*='input-RequestDetailExpenseAccountItem'].v-select`

- 内部の `input` が disabled、または値が入っている場合は**自動入力済みなので触らない**
- 空の場合のみ、select をクリック → 確定した内訳を入力 → Enter

### 内容・メモ

プレースホルダ「内容・メモ」の入力欄。disabled または値が入っていれば触らない。

**空の場合は、空のままでよい。** 「内容・メモは必須項目です」と警告が出るが、下書き保存は妨げられない。過去の承認済み申請でも空欄のまま通っている。判定表に記入値の定義が無い限り、**推測で埋めない**。

組織として記入する運用があるなら、判定表に列を足してから使う。

## 4. 下書き保存

ボタン「下書きに保存」をクリック。保存後のURLが申請の下書きURL。

**下書き保存までで止める。申請の提出はしない。**

## 既知の落とし穴

| 事象 | 対処 |
|---|---|
| 「同じ支払い先の過去申請から、継続的に使用している項目を入力しました」というポップアップが出る | 自動入力が走っている。各項目を入力前に必ず既存値を確認する。ポップアップは自動で消えるので待つ |
| 内訳の select に値が入っているのに上書きしてしまう | disabled と現在値の両方をチェックしてから入力する |
| 未申請タブだけ見て「明細が無い」と報告してしまう | 申請済タブを必ず確認する。既に申請済みのことがある |
| 稟議を「関連申請」に紐付けてしまう | 原則は明細行の「購買申請」。関連申請欄は使わない |
| 稟議検索の結果の先頭をそのまま選ぶ | 年度違いが並ぶ。サービス期間と利用可能額を照合して選ぶ |
| 「内容・メモは必須項目です」で手が止まる | 空欄のまま下書き保存できる。推測で埋めない |
| ファイル添付のダイアログが閉じない | 2段構造。2段目は自動で閉じるが、1段目は `button.close` で閉じる |
| 同じ明細セルを何度も開き直す | ファイル添付と購買申請の紐付けは同じセル内。添付を先にして、開いたついでに紐付ける |
| 稟議が見つからないのに処理を止めてしまう | 下書きは保存できる。未紐付けであることを利用者に明示して続行する |
| ファイルを二重添付してしまう | 「ファイルは必須です」の有無で判断する |
| 稟議検索でタブを切り替え忘れる | 「閲覧できる申請」タブを必ずクリックする |
| 稟議番号が `0` 始まり | 番号欄には入力せず、件名やキーワードで検索する |
| 画面遷移直後に操作して失敗する | 各遷移後、対象要素が表示されるまで待つ |
| 請求書PDFをアップロードしようとして「ファイルにアクセスできない」となる | Playwright MCP は既定でワークスペース配下のファイルしか扱えない。`.playwright-mcp/` にコピーして添付し、**添付後に削除する**（`.playwright-mcp/` は `.gitignore` に入れておく） |

## セレクタが合わない時

バクラクの画面変更でセレクタが変わることがある。実績として、ログイン画面と申請フォームは年に数回変更されている。

対処の順序:

1. 該当箇所のみ、実画面の構造を確認して代替セレクタを特定する（画面全体のスナップショットは高くつくので、範囲を絞る）
2. 作業を続行できるなら続行し、**利用者にどのセレクタがズレていたかを報告する**
3. このファイルの記述を更新する

ラベルやボタン名（「申請する」「下書きに保存」など）はセレクタより安定しているため、CSS セレクタが壊れた場合はテキストベースの指定に切り替えると復旧しやすい。
